이 스레드가 하는 일

WholeBodyControlThread(Th4)는 지면이 로봇에 가해야 할 힘(wrench) 을 계산합니다. 출력은 발마다 [Fx, Fy, Fz, τx, τy] 5개입니다. Kinematics 스레드의 ID 단계가 이 힘을 τ = g(q) − Jᵀw로 관절 토크에 반영합니다.

계산 방법은 자세 MPC(모델 예측 제어) 입니다. "몸통을 수평으로 유지하려면 앞으로 0.2초 동안 접촉 힘을 어떻게 줘야 하는가"를 작은 QP(이차계획) 문제로 풀어 첫 스텝의 힘을 씁니다.

  • 1 kHz 루프로 돌지만 MPC는 200 Hz(5틱=5 ms마다)로 풀고, 사이 틱은 직전 해를 유지합니다.
  • WBC는 wbc on 상태이고 walk 모드일 때만 동작합니다. 꺼져 있으면 모든 wrench가 0입니다.

물리 모델 (슬라이드 "MPC")

몸통(질량 M, 관성 I) 하나와 질량이 없는 다리로 이루어진 단순 모델입니다. 접촉점이 COM에 대해 (x, y, z) = COM − 접촉점에 있을 때, 접촉 힘이 COM에 거는 회전 토크는

  • Iy·θ̈y = x·Fz − z·Fx + τy (pitch)
  • Ix·θ̈x = z·Fy − y·Fz + τx (roll)

입니다(접촉점 위치 벡터 × 힘 + 발목 모멘트). 상태는 x = [θx, θ̇x, θy, θ̇y](몸통 roll/pitch와 각속도), 입력은 u = [Fx, Fy, Fz, τx, τy].

이산화(Δt=20 ms): θ_{k+1} = θ_k + Δt·θ̇_k, θ̇_{k+1} = θ̇_k + Δt/I · (위 식의 우변). (x,y,z)가 스텝마다 달라서(발이 움직임) 입력 행렬 B_k가 시간에 따라 변합니다.

주의 슬라이드의 이산 행렬에서 θ̇y 행의 Fz 계수가 −x/I로 적혀 있지만, 같은 슬라이드의 연속식과 물리(COM 앞쪽 x에서 …)는 +x/I입니다. 코드는 연속식을 따릅니다.
  • 중력과 코리올리는 모델에 넣지 않았습니다. 대신 힘의 기준값 f_ref에 Fz = m·g(+높이 PD)를 넣고, 입력이 이 기준에서 벗어나는 만큼에 비용을 줍니다.
  • 수평력 기준 = m × 계획 COM 가속도: LIPM 보행에서 지면이 주는 수평력이 정확히 이 값입니다(모멘트는 0, ZMP=발목). 그래서 MPC는 "계획대로 걸을 때의 힘"을 기준으로 삼고 자세 오차만 보정합니다.
  • 제약(스텝마다): 0 ≤ Fz ≤ 2mg, 마찰 피라미드 |Fx|,|Fy| ≤ μFz (μ=0.5), CoP가 발 안 −0.115·Fz ≤ τy ≤ 0.045·Fz(발목 기준 발끝 11.5 cm / 뒤꿈치 4.5 cm: 앞뒤 비대칭), |τx| ≤ 0.025·Fz.

두 발을 하나로: 유효 접촉점

발이 둘이라도 MPC에는 접촉점 하나만 넣습니다. 각 발이 같은 wrench u를 비중 w_L, w_R(합 1)대로 나눠 가지면, 합 토크는 정확히 r_eff × F + τ (r_eff = w_L·r_L + w_R·r_R)가 되므로 근사가 아닙니다. 출력은 wrench_i = w_i · u.

비중 w는 계획 ZMP로 정합니다: ZMP_y = COM_y − (h/g)·a_y 를 두 발 y 사이에서 선형 분배(한발지지에서는 ZMP=지지발이라 1).

한 틱의 흐름

  1. wbc 꺼짐? — 모든 wrench 0으로 쓰고 다음 틱 (상태 초기화)
  2. 200 Hz 풀이 시점인가? — 5틱(5 ms)마다 한 번만 MPC를 풉니다
  3. 기하 만들기 — 실측 COM·발 위치(k=0) + MotionGen 계획(k≥1)을 섞어 N=10 스텝의 COM−발 상대위치 `r`
  4. 접촉 비중 — 스텝마다 계획 ZMP로 계산, k=0은 실제 접촉 판정으로 마스킹
  5. 힘 기준 `f_ref` — 수평 m·a(계획 가속도), 수직 m·g + 높이 PD
  6. MPC 풀이 — 초기 상태 = IMU 각도/각속도. 성공하면 `u_hold` 갱신
  7. 분배·출력 — 매 틱 `share_i × u_hold`를 DataWarehouse에 씀

이렇게 만들게 된 이유 (헤드리스 폐루프 시험으로 발견)

MuJoCo를 GUI 없이 실제 컨트롤러와 연결해 돌리는 도구(tools/walk_sim)로 확인한 세 가지입니다.

  • 전신 COM ≠ pelvis: G1의 전신 COM은 pelvis 프레임 원점보다 x로 약 4.4 cm 앞, z로 약 7.9 cm 아래에 있어서(pelvis 링크 질량중심과도 x로 4.4 cm 차이), pelvis를 COM으로 쓰면 정적 모멘트 m·g·x가 틀립니다. pinocchio 정적 평형으로 확인(기저 잔차: 참 COM 0 / 모멘트 0 −9.8 Nm / pelvis 기준 −14.3 Nm). → 실측 전신 COM 사용.
  • 시간 기준 지지발 교대는 위험: "DSP 정확히 중간에 하중을 넘김"은 COM이 새 지지발 위에 오기 전에 이전 발 하중을 빼서 피드포워드가 실제 하중 분배와 어긋났고 약 1.4초 만에 넘어졌습니다. → ZMP 기준 비중.
  • Fx/Fy를 0으로 묶으면 안 됨: LIPM 보행의 올바른 지면반력은 "모멘트 0, 수평력 = m·a"인데, Fx/Fy를 막으면 MPC가 COM이 발에서 7.5 cm 안쪽인 순간을 모멘트(τx≈−24 Nm)로 버티려다 CoP 한계(±13 Nm)에 막힙니다. → 수평력 기준 = m·계획가속도.

튜닝 포인트

  • gain wbc a b c d e: 앞 4개는 상태 가중의 제곱근(Q = diag(a², b², c², d²), 기본 300/30/300/30), 5번째는 Fz 높이 PD 이득(기본 2000).
  • kInputWeight = [50, 50, 0.2, 0.1, 0.1]: Fx·Fy는 크게(기준 근처 고정), Fz는 보통, 토크는 작게(자세 보정에 적극 사용).
  • kFootHeelM/kFootToeM/kFootHalfWidthM(g1_joints.h의 발 접지 범위), kFrictionMu: 접촉 제약 크기. kOffsetDecayPerStep(0.85), kOffsetClampM(5 cm): 실측-계획 오차의 반영 정도.

용어 정리

  • wrench: 힘(3) + 모멘트(2~3). 여기서는 발목 프레임 원점 기준, 월드 방향 축.
  • CoP / ZMP: 지면반력이 작용하는 점(압력 중심). 발 안에 있어야 발이 안 뒤집힙니다.
  • QP / OSQP: 이차 비용 + 선형 제약을 푸는 최적화 / 그 라이브러리.
  • MPC: 앞으로 N스텝을 예측해 최적 입력열을 구하고 첫 입력만 쓰는 것을 반복하는 제어.
