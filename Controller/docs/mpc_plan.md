# 자세 MPC 계획 (WBC 스레드) — 슬라이드 "MPC" 기반, OSQP QP

> 기존 WBC(몸통 PD + 발별 50/50 배분 + 발별 Fz 클램프 QP)는 삭제하고 이 MPC로 대체했다.
> 구현: `include/attitude_mpc.h`, `src/attitude_mpc.cpp`, `src/wbc_thread.cpp`. 검증: `tools/mpc_check`, `tools/gait_check`(접촉 비중/Preview).
> 보행 패턴(`walking_pattern_plan.md`)과의 접점: MotionGen이 향후 발 위치/접촉 비중(Preview)을 MPC에 준다.

---

## 1. 모델 (슬라이드)

몸통(질량 M, 관성 I) + 질량 없는 다리. 접촉점이 COM 기준 `(x,y,z) = COM − 접촉점` 일 때

```
Iy θ̈y = x·Fz − z·Fx + τy
Ix θ̈x = z·Fy − y·Fz + τx
```

- 상태 `x = [θx, θ̇x, θy, θ̇y]`, 입력 `u = [Fx, Fy, Fz, τx, τy]` (지면이 로봇에 가하는 접촉 wrench, 발목 프레임 원점 기준 — ID의 `−Jᵀw` 규약과 동일).
- 이산화(오일러, Δt): `θ_{k+1} = θ_k + Δt θ̇_k`, `θ̇_{k+1} = θ̇_k + Δt·(B_k u_k)`. `B_k`는 스텝마다 `(x,y,z)`가 달라 **시변**.
- ⚠️ 슬라이드 이산 행렬 θ̇y 행의 Fz 계수는 `−x/I` 로 적혀 있으나, 같은 슬라이드의 연속식과 물리(발이 COM 뒤에서 위로 밀면 앞으로 숙임)는 `+x/I`. **연속식을 따랐다.**
- 중력/코리올리는 모델에서 제외하고 Fz 기준값에 `m·g`(+높이 PD)를 넣는다 → 비용에서 `u`를 `u_ref=[0,0,fz_ref,0,0]` 쪽으로 정규화. (슬라이드의 "MPC output에 중력 term 더해 줌"과 같은 효과. 단 COM이 발 앞뒤로 어긋난 만큼의 정적 토크 `m g x`는 모델의 `x·Fz` 항이 그대로 반영하므로 **CoP 이동(τy ≈ −m g x)이 자연스럽게 나온다** — `mpc_check` 2번.)

## 2. QP 구성

- 변수 `z = [x_1..x_N, u_0..u_{N−1}]` (N=10 → 90개), 초기 상태는 매개변수. 희소 형태 그대로 OSQP.
- 비용: `Σ x_kᵀQx_k (마지막은 ×5) + Σ (u_k−u_ref)ᵀR(u_k−u_ref)`, 상태 기준 0 (몸통 수평).
- 제약(스텝마다): `0 ≤ Fz ≤ 2mg`, 마찰 피라미드 `|Fx|,|Fy| ≤ μFz (μ=0.5)`, CoP `|τy| ≤ 0.08·Fz`, `|τx| ≤ 0.04·Fz`.
- 가중치: `Q = diag(gain²)` — `gain wbc kp_r kd_r kp_p kd_p kp_h`의 앞 4개를 상태 가중의 제곱근으로 재해석(기본 300/30/300/30), `kp_h`는 Fz 높이 PD (그대로). `R = [50, 50, 0.2, 0.1, 0.1]`.
- **Fx/Fy를 크게 막는 이유**: 모델에 COM 병진 동역학이 없어서, 가중이 작으면 MPC가 병진 힘(−z·Fx)으로 토크를 만들어 낸다(`mpc_check`에서 확인: R=1이면 Fx≈10 N을 상시 사용). 기존 WBC가 Fx=Fy=0이던 것과 같은 이유.
- 풀이는 1 kHz (`kMpcSolvePeriodTicks=1`, 이전 5틱=200 Hz, 처음엔 10틱=100 Hz), 사이 틱은 직전 해를 유지. MotionGen의 미래 발 위치(Preview) 갱신도 같은 주기. 풀이 시간 평균 ~0.1 ms(`mpc_check`), 컨트롤러 실행 중 WBC 연산 평균 0.03 ms / 최대 0.6 ms.

## 3. 요청 사항에 대한 결정과 추천

### 3.1 지지발 교대 / 접촉 비중 — ⚠️ "DSP 중간 시간 교대"는 시뮬에서 넘어져 **ZMP 기준**으로 바꿨다
- 처음 구현: `w_left(t)`를 DSP(및 Init)의 정확히 중간에서 이전 지지발 → 새 지지발로 넘김(`lipm_gait.h`의 `HandoverWeight`, 40 ms smoothstep). 폐루프 하네스(`tools/walk_sim`)에서 `m w` 후 **약 1.4초 만에 넘어졌다**: Init 중간에 오른발 하중이 0이 되는데 그때 COM은 아직 양발 한가운데(y≈0)라, 피드포워드가 "왼발이 전부 받는다"고 가정해 실제 하중 분배와 어긋남.
- 현재(WBC): 접촉 비중 = **계획 ZMP** 기준. `ZMP_y = COM_y − (h/g)·a_y` (LIPM)를 두 발 y 사이에서 선형 분배, SSP에서는 ZMP=지지발이라 1. COM이 새 발 위로 오는 만큼 하중이 넘어간다. 같은 시나리오에서 제자리 걸음이 안정(최대 기울기 0.04 rad)했다.
- `lipm_gait.h`의 `w_left`/`HandoverWeight`는 그대로 남아 있고(gait_check 검증), Preview에 실려 오지만 WBC는 ZMP 비중을 우선 쓴다 (ZMP 분모가 0에 가까울 때만 `w_left` 폴백).
- MPC 모델에는 유효 접촉점 `r_eff = w_L·r_L + w_R·r_R`로 넣고, 출력은 `wrench_i = w_i · u_0` (두 발이 같은 wrench를 비중대로 나눠 가지면 합 토크가 정확히 `r_eff × F + τ`).

### 3.1b 힘 기준값 = 계획 COM 가속도 (하네스로 발견한 두 번째 문제)
- LIPM 보행의 올바른 지면반력은 **모멘트 0(ZMP=발목), 수평력 = m·COM가속도**다. 처음엔 Fx/Fy를 0으로 강하게 묶었더니 MPC가 COM이 지지발에서 0.075 m 안쪽인 순간을 모멘트(τx≈−24 Nm)로 버티려 했고, CoP 한계(±0.04·Fz≈13 Nm)에 막혀 불가능했다.
- 지금: `u_ref = [m·a_com(계획), m·g(+높이 PD), 0, 0]`를 스텝별로(`f_ref[k]`) 주고 R로 그 근처에 묶는다. Preview가 계획 COM 가속도(`com_acc`)를 함께 전달한다 (SSP: LIPM `ω²(COM−지지발)`, DSP/Init: Hermite 2계도함수).

### 3.2 COM 대비 발 위치의 갱신 — 추천: **계획 기반 예측 + 실측 보정 (하이브리드)**
- 실시간 센싱만 쓰면 향후 스텝의 발 위치를 알 수 없어(현재 값을 N스텝 동안 고정하는 꼴) 스윙/교대 때 B_k가 틀린다. 계획만 쓰면 오도메트리 드리프트·착지 오차·실제 몸통 위치 차이를 못 본다.
- ⚠️ **COM은 pelvis가 아니라 실측 전신 COM**(`ComMeasWorld`, pinocchio `centerOfMass`)을 쓴다. G1은 walkready 자세에서 COM이 pelvis보다 약 4.4 cm 앞이고, pelvis를 COM으로 쓰면 정적 모멘트 `m·g·x`가 틀려 오히려 기존 PD보다 나빠졌다(pinocchio 정적 평형 기저 잔차: 참 COM 0 / 모멘트 0 −9.8 Nm / pelvis 기준 −14.3 Nm). 계획은 pelvis 기준이라 `pelvis→COM` 오프셋을 더해 COM 기준으로 변환한다.
- 구현: k=0은 **실측**(`FootPosMeasWorld`와 pelvis 위치로 `COM−발목`), k≥1은 **MotionGen 계획**(`WalkPreview`: 발바닥 + `kFootSoleOffsetM`, 계획 COM). k=0의 (실측 − 계획) 오차를 `0.85^k`로 감쇠시키며 향후 스텝에 더하고 ±5 cm로 제한 → 가까운 미래는 실측, 먼 미래는 계획을 믿는다.
- 접촉 비중도 k=0만 실제 접촉 판정(`FootContact`)으로 마스킹·재정규화 (이륙/착지 지연 대응). 계획이 없으면(Walk 아님 등) 실측 기하 고정 + 접촉 센서 비중으로 폴백.
- Preview는 `WalkPatternGenerator::Preview()`가 생성기를 복사해(보정기 고정) 1 kHz 틱으로 앞서 진행시켜 20 ms 간격 10점을 뽑는다. `gait_check`가 "Preview == 실제 진행" 오차 0을 확인.

### 3.3 예측 구간 — 추천: **N=10, Δt=20 ms (0.2 s), 200 Hz 재계산**
- 10스텝이라는 N은 적절하다. 이 시스템에서 Δt가 더 중요: 자세 동역학은 `θ̈=τ/I`(I≈3.5)로 빠르고(수 Hz 이상) 접촉 교대 DSP가 0.14 s이므로 **Δt=20 ms면 DSP 안에 7점, 교대(중간)를 정확히 포착**하고, N·Δt=0.2 s는 SSP(0.56 s)의 1/3 정도를 내다봐 교대 직전 준비에 충분하다.
- Δt를 키워(예: 70 ms로 0.7 s=한 스텝 전체) 길게 보면 DSP/교대가 한두 점으로 뭉개지고 오일러 이산화 오차도 커진다. 더 길게 보고 싶으면 N을 늘리기보다 **뒤쪽 스텝만 Δt를 키우는 비균일 격자**가 맞다(후속 과제).
- 계산량: 희소 QP 90변수/130제약, 평균 ~0.1 ms → 200 Hz에서도 1 ms 루프에 안전(WBC 연산 평균 0.05 ms, 틱별 최대 0.47 ms). 매 틱(1 kHz) 풀 필요는 없다(자세 PD가 아니라 계획성 입력이므로 ZOH로 충분).

## 3.4 폐루프 검증 (`tools/walk_sim`, 헤드리스 MuJoCo + 실제 controller)
- GUI 없이 실시간(1 ms)으로 `controller`를 별도 IPC 큐(`WKJ_IPC_KEY`)로 붙여 스크립트 명령/외란을 준다. 실행 예:
  `walk_sim 34 "cmd=0.5:m wr" "cmd=3.5:d a" "cmd=9:m w" "cmd=9:v 0" "cmd=9:wb on" "cmd=16:v 0.1" "cmd=23:v 0.2"`
  (`push=<t>:<fx>:<fy>:<dur>`로 외력, `csv=`로 pelvis 로그). 시뮬 GUI/컨트롤러가 떠 있어도 큐가 분리돼 있지만 CPU는 공유한다.
- 결과(푸시 없음, WBC on): 제자리 걸음 유지, 0.1→0.2 m/s 전진 약 2.7 m 안정. (참고: 이전 구현에서는 `m w` 후 1.4초 내 낙하.)
- 참고: **WBC off**에서는 지지다리 하중을 받치는 피드포워드(`g(q)−Jᵀw`)가 없어 관절 PD만으로 단일 지지를 버텨야 하므로 `m w` 후 약 2.5초 만에 넘어졌다 (발 보정 게인과 무관). 발 위치 보정은 WBC on 상태에서 평가해야 한다.

- 푸시 생존은 위상 의존이 크다: 보정 0에서도 옆 40 N가 2/7 위상에서만 버티고, 앞뒤 푸시는 120 N까지 버텼다(150 N부터 낙하). 즉 병목은 게인이 아니라 보정 구조(기울기 → 착지 위치)와 옆 방향 복원력이다.
- 개선 후보: (1) 기울기 대신 계획 대비 실측 COM 위치/속도 오차로 캡처포인트 보정, (2) 보정이 COM 계획을 새 발에 재앵커하는 되먹임이 고게인에서 불안정을 만드는지 분리(발만 옮기고 COM 계획은 유지), (3) 푸시 직후 스텝 타이밍 조정.

## 3.6 COM 기준점과 발 형상 (pelvis 프레임 ≠ 링크 질량중심 ≠ 전신 COM)
- ① pelvis 프레임 원점, ② pelvis 링크 질량중심(URDF `<inertial>`: 프레임보다 **7.6 cm 아래**), ③ 전신 COM. 걷기 자세에서 ③은 ①보다 x +4.4 cm / z −7.9 cm, ②보다 x +4.4 cm / z −0.3 cm. 예전에는 ①을 COM 목표로 썼다.
- 지금: Kinematics가 **전신 COM**이 COM 목표에 오도록 root(①)를 `COM목표 − com_off`에 둔다. `com_off`는 직전 틱 IK 해의 `COM(q) − root`(자세에 따라 x 1.8~6.6 cm 변함, 오프라인 시험에서 약 4 ms에 1 mm 이하로 수렴). LIPM의 h는 전신 COM 높이 0.664 m(`kNominalComHeightM`).
- **발 접지 중앙은 발목보다 3.5 cm 앞**(g1.xml 접지 구 x −0.05 ~ +0.12). COM을 발목 위에 정확히 두자 뒤 푸시에 약해져(100 N 0/6) 보행 계획의 ZMP/COM 기준점을 발 중앙(`GaitParams.zmp_dx = kFootCenterOffsetX`)으로 옮겼다. MPC의 CoP 제약도 발목 기준 비대칭(`−0.115·Fz ≤ τy ≤ 0.045·Fz`, `|τx| ≤ 0.025·Fz`)으로 고쳤다.
- 푸시 시험(WBC on, 보정 0, 푸시 0.1 s, 6~7개 위상): 푸시 없음 6/6, 앞뒤 100 N 12/12, 옆 40 N 14/14. 옆 80 N 이상, 앞뒤 150 N 이상은 여전히 넘어짐.

| COM 오차 k=1.0 | 10 | **19** |
| COM 오차 k=1.5 | 7 | – |

- **COM 오차 기반(구현 후 제거)**: `ξ = (p_meas − p_plan) + (v_meas − v_plan)/ω` 를 착지 위치 보정으로 사용하고, 로봇이 처지는 정적 오차는 1.5 s 시정수 기준선으로 뺐다(오프라인 `gait_check`에서 정적 오차 3 cm 무시·+5 cm 유지 오차에 착지 +2.6 cm 이동 확인). 그러나 폐루프에서 **보정 없음보다 8~9회 적게 버팀(26 → 18~19)**. 보정이 COM 계획을 새 발에 재앵커하기 때문에 계획 pelvis가 밀린 방향으로 같이 움직이고, 계획 대비 추종 지연(수 mm~cm, 위상 의존)이 매 스텝 보정에 섞여 걸음을 흔드는 것으로 보인다(원인 분리는 안 함). 해롭다고 판단해 코드를 제거했다.
- **기울기 기반**: 소게인(0.2/0.05)은 보정 없음과 사실상 동일(26 vs 27), 게인을 키우면 나빠진다. 개선 증거가 없어 **기본값 0 유지**(`gain foot kp kd`로 켤 수 있음).
- 시사점: 현재 병목은 "발을 어디에 딛는가"가 아니라, 큰 외란에서 한발지지 중 토크/CoP 여유와 위상(스윙 시작 직후 등)이다. 개선하려면 스텝 타이밍(조기 착지)이나 COM 계획을 외란에 맞춰 재계획하는 쪽이 필요하다.

## 5. 알려진 한계 / 후속
- 모델은 **자세(roll/pitch)만**. COM 병진·높이는 모델에 없고 Fz만 높이 PD 기준으로 조정 → Fx/Fy는 사실상 0. 병진까지 넣으려면 상태에 COM 위치/속도 추가(중력 포함)가 필요.
- 관성은 neutral 자세 한 값(Ixx≈3.67, Iyy≈3.38) 고정. 보행 자세 변화는 무시.
- IMU 각속도를 θ̇로 그대로 사용(body/world 좌표계 확인 필요 — 작은 각도에서는 차이 미미).
- 시뮬레이션 검증 전: 가중치(`gain wbc`)와 `R`, `kHandoverWidthS`, CoP 한계는 실기 튜닝 대상. 문제 시 `wb off`로 끄고, 계획 없이 센서만 쓰는 폴백으로 원인 분리.
